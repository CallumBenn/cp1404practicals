## Three lessons I've learned about "clean code":

- ### Don't Repeat Yourself (DRY)
  If some functionality is used more than once throughout a program, find ways to store that functionality once, then
  'call' it where needed.
- ### Naming
  Functions, variables, classes, constants, and so on need to comply with established style standards (PEP 8), as to
  avoid implicit and inconsistent naming.
- ### Comments and Docstrings
  The purpose of code isn't always obvious to those inspecting it. Writing comments (where needed) to accompany code and
  docstrings describing the purpose of functions/the whole program minimizes room for interpretation on the inspector's
  part.
